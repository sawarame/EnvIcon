## User Scenarios & Testing *(mandatory)*

### User Story 1 - ポート番号およびパスを含むURLパターンの設定と環境識別 (Priority: P1)

開発者やサイト運用者が、オプション設定画面の既存の1行パターン入力欄にポート番号付きアドレス（例: `localhost:3000`）やパス付きアドレス（例: `example.com/stg`）を入力することで、同一ドメインであってもポート番号やサブディレクトリごとに異なる環境バッジ（Favicon・ページ内バッジ・ツールバーアイコン・コンソール表示）を正確に識別できるようにする。

**Why this priority**: ローカル開発におけるポート番号違いのサーバー併用や、同一ドメイン配下のサブディレクトリでステージング・管理画面を運用するケースに対応することが本機能の中核価値であるため。

**Independent Test**: オプション設定画面で `localhost:3000` を開発環境、`localhost:8080` をステージング環境、`example.com/stg` をステージング環境に登録し、該当URLおよび類似URL（`example.com/staging` 等）へアクセスした際のバッジ表示有無を検証することで単独テストが可能。

**Acceptance Scenarios**:

1. **Given** 開発環境に `localhost:3000`、ステージング環境に `localhost:8080` が登録されている状態、**When** ユーザーが `http://localhost:3000/dashboard` を開く、**Then** 開発環境のバッジ表示が適用され、`http://localhost:8080/dashboard` を開いた場合はステージング環境のバッジ表示が適用される。
2. **Given** ステージング環境に `example.com/stg` が登録されている状態、**When** ユーザーが `https://example.com/stg` または `https://example.com/stg/users` を開く、**Then** ステージング環境として一致するが、`https://example.com/staging` や `https://example.com/` を開いた場合は一致しない。
3. **Given** ステージング環境に大文字を含む `example.com/Admin` が登録されている状態、**When** ユーザーが `https://example.com/Admin/settings` を開く、**Then** 一致するが、パスの大文字・小文字が異なる `https://example.com/admin/settings` を開いた場合は一致しない。
4. **Given** ユーザーがオプション設定画面のパターン入力欄に `https://Example.COM:8080/stg/?tab=1#section` のようなフルURLを入力した状態、**When** 設定が自動保存される、**Then** プロトコル・クエリ・ハッシュ・末尾スラッシュが取り除かれ、ホスト名が小文字化された `example.com:8080/stg` として正規化・保存される。

### User Story 2 - 詳細度に基づく優先判定と正規表現の後方互換マッチ (Priority: P2)

同一サイトに対して広域なルール（例: 本番環境に `example.com`）と限定的なルール（例: ステージング環境に `example.com/stg` や `example.com:8080`）を併用した際、環境の並び順にかかわらず具体的なパターンが自動的に優先適用される。また、正規表現モードでも既存のホスト名用パターンを維持したままポート・パスを含む正規表現を利用でき、URLチェッカーで実際に採用されるルールを1つだけ確認できる。

**Why this priority**: 親ドメイン全体と特定サブディレクトリ・特定ポートで環境が異なる実運用構成を設定順の制約なく表現できるようにし、かつ既存ユーザーの正規表現資産を壊さないために不可欠であるため。

**Independent Test**: リスト上位の本番環境に `example.com`、下位の開発環境に `example.com/dev` を登録し、URLチェッカーおよび実画面で `https://example.com/dev/page` を確認した際に開発環境が選ばれ、該当する1行のみがハイライトされることで検証できる。

**Acceptance Scenarios**:

1. **Given** 本番環境に `example.com`、ステージング環境に `example.com:8080`、開発環境に `example.com:8080/dev` が登録されている状態、**When** ユーザーが各アドレスへアクセスする、**Then** 詳細度（深いパス指定 ＞ ポート指定あり ＞ ホスト名のみ）に従い、`:8080/dev` 配下では開発環境、それ以外の `:8080` ではステージング環境、標準ポートの他パスでは本番環境が適用される。
2. **Given** 既存のホスト名向け正規表現パターン `^.*\.local$` が登録されている状態、**When** ユーザーがパス付きの `http://myapp.local/dashboard` を開く、**Then** 後方互換判定により従来通り一致し、かつ新たに `^localhost:300[0-9]/admin` のようなポート・パスを含む正規表現を登録した場合も正しく一致する。
3. **Given** 複数の環境のパターンに同時に一致するURLがある状態、**When** オプション設定画面のURLチェッカーにそのURLを入力する、**Then** 優先順位ルールで最終的に採用された環境のバッジが表示され、採用された1つのパターン入力行のみが一致状態としてハイライトされる。

### User Story 3 - クイック操作ポップアップでのポート単位操作と誤編集防止ロック (Priority: P2)

ツールバーのクイック操作ポップアップから、現在開いているページの `ホスト名[:ポート番号]` 単位でワンクリック環境登録・解除およびサイト単位の一時OFFを行える。一方、パス指定・正規表現・ポートなし親ホスト設定によって一致しているページでは、誤って共有ルールを削除・上書きしないようロック案内を表示して設定画面へ誘導する。

**Why this priority**: ローカル開発で頻繁に発生するポート別の環境割り当てや一時ミュートを素早く行えるようにしつつ、設定画面で定義した詳細なパスルール等の意図しない破壊を防ぐため。

**Independent Test**: `http://localhost:3000/app` 上でポップアップから環境登録と一時OFFを行い `http://localhost:8080/app` に影響しないこと、および `example.com/stg` ルール一致ページでポップアップを開いた際に編集ロック案内が表示されることで単独検証できる。

**Acceptance Scenarios**:

1. **Given** 未登録の `http://localhost:3000/users` を開いている状態、**When** ポップアップから開発環境ボタンをクリックする、**Then** `localhost:3000` が開発環境に登録され、続けて「このサイトを一時OFF」を有効にすると `localhost:3000` のみが一時OFFとなり `localhost:8080` のバッジ表示は維持される。
2. **Given** パス指定パターン `example.com/stg`、正規表現パターン、またはポートなし親ルール `localhost`（アクセス先が `localhost:3000` の場合）によって環境に一致している状態、**When** ポップアップを開く、**Then** 環境変更・解除ボタンの代わりに一致中のパターン情報とロック案内が表示され、オプション設定画面を開くボタンが提示される（一時OFFスイッチは引き続き操作可能）。

### User Story 4 - ページ再読み込みを伴わない画面内遷移へのリアルタイム追従 (Priority: P3)

シングルページアプリケーション等でページ全体を再読み込みせずにURLパスが切り替わった際、遷移先のパスに応じてFavicon・ページ内バッジ・ツールバーアイコンがリアルタイムに更新・復元され、判定環境が変化したときのみコンソールへ環境名が出力される。

**Why this priority**: 画面内遷移を多用するモダンなWebアプリケーションにおいて、パス変更後も変更前の環境バッジが残り続けることによる環境誤認を防ぐため。

**Independent Test**: ページ再読み込みなしでパスが遷移するサイト上で、未登録パスから登録済みパス（例: `/stg/dashboard`）へ移動し、さらに未登録パスへ戻った際の表示更新とコンソール出力回数を観察することで検証できる。

**Acceptance Scenarios**:

1. **Given** `example.com/stg` のみがステージング環境に登録されている状態、**When** ユーザーが `https://example.com/home` から画面内遷移で `https://example.com/stg/list` へ移動し、その後 `https://example.com/about` へ移動する、**Then** `/stg/list` 到達時にリロードなしでバッジ類が即座に適用され、`/about` 移動時にはサイト本来のFaviconおよびバッジなし状態へ完全に復元される。
2. **Given** `example.com/stg` 配下でコンソール表示が有効な状態、**When** `/stg/list` から同じステージング環境内の `/stg/detail` へ画面内遷移する、**Then** コンソールログは重複出力されず、未一致状態や別環境から当該環境へ切り替わったときのみ環境ログが出力される。

---

### Edge Cases

- トップページの末尾スラッシュのみが付いたURL（例: `https://example.com/` や `localhost:3000/`）が入力された場合は、パス指定なし（`example.com` や `localhost:3000` 全体）として正規化される。
- 標準ポート番号が明示されたURL（`http://example.com:80/path` や `https://example.com:443/path`）の入力やアクセスが発生した場合は、標準ポート省略時のアドレス表現と整合するよう正規化され、不一致が発生しないようにする。
- 階層の深さが異なる複数のパス指定（例: `example.com/app` と `example.com/app/stg`）に同時一致する場合は、より階層が深く具体的な `example.com/app/stg` が優先される。
- 同一の詳細度スコアを持つパターンが複数環境（または同一環境内）で競合する場合は、環境の並び順（上から順）および環境内のパターン並び順（上から順）に従って先頭のものが確定的に選ばれる。
- 表記揺れを含む同一対象パターン（例: `https://Example.COM/stg/?foo=bar` と `example.com/stg/`）が複数登録された場合は、正規化後の値に基づいて重複エラーとして検知し保存を保留する。
- 範囲外のポート番号（例: `example.com:70000` や `example.com:0`）や数値以外のポート指定（例: `example.com:abc`）が入力された場合は、不正な入力としてエラー強調し保存を保留する。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムは、オプション設定画面の既存の単一パターン入力欄において、`ホスト名`、`ホスト名:ポート番号`、`ホスト名/パス`、および `ホスト名:ポート番号/パス` の入力を受け付け、含まれる要素から判定範囲を自動判別しなければならない（MUST）。
- **FR-002**: システムは、通常モードの入力値からプロトコル（`http://`、`https://` 等）、クエリパラメータ（`?...`）、ハッシュフラグメント（`#...`）、およびパス末尾のスラッシュ（`/`）を除外して正規化しなければならず、パスが `/` のみの場合はパス指定なしとして扱わなければならない（MUST）。
- **FR-003**: システムは、通常モードにおいてホスト名部分を小文字に正規化して大文字・小文字を区別せずに判定し、パス部分は入力された大文字・小文字を維持して区別（ケースセンシティブ）して保存・判定しなければならない（MUST）。
- **FR-004**: システムは、ホスト名構文およびポート番号の範囲（1〜65535 の整数）を検証し、不正な形式や正規化後に他パターンと重複する入力に対してエラー表示を行い保存を保留しなければならない（MUST）。また HTTP の標準ポート（80）および HTTPS の標準ポート（443）の表記有無による不一致が生じないよう正規化しなければならない（MUST）。
- **FR-005**: システムは、通常モードでポート番号を持たないパターンを任意のポート番号に一致させ、ポート番号を持つパターンを指定されたポート番号のみに一致させなければならない（MUST）。
- **FR-006**: システムは、通常モードでパスを持つパターンについて、スラッシュ（`/`）を区切りとするセグメント境界での配下一致（指定パスとの完全一致、または指定パス直後に `/` が続く配下パスへの一致）として判定し、単なる前方文字列一致となる別名パス（例: `/stg` に対する `/staging`）には一致させてはならない（MUST NOT）。
- **FR-007**: システムは、正規表現モードにおいて、プロトコル・クエリ・ハッシュを除いた `ホスト名[:ポート番号]/パス` に対して一致判定を行うとともに、後方互換性のためパターン内に `:` および `/` を含まない正規表現についてはホスト名単体に対しても一致判定を行わなければならない（MUST）。
- **FR-008**: 現在のURLが複数の有効なパターンに同時に一致する場合、システムは詳細度の高い順（`1. パス指定あり［より深い・長いパスを優先し、同一パスではポート指定ありを優先］ ＞ 2. ポート指定あり［パスなし］ ＞ 3. ホスト名のみ`、同一階層内では通常パターンを正規表現より優先、さらに同条件の場合は環境の上から順およびパターンリストの上から順）によって適用する単一の環境とパターンを決定しなければならない（MUST）。
- **FR-009**: システムは、既存のホスト名のみで構成された保存済み設定データを、ユーザーによる移行操作なしでそのまま全ポート・全パス対象のホスト名パターンとして互換動作させなければならない（MUST）。
- **FR-010**: クイック操作ポップアップは、アクティブなページの `ホスト名[:ポート番号]`（非標準ポート使用時はポート番号を含む）を表示および操作の単位とし、ワンクリック環境登録・解除およびサイト単位の一時OFFをこの単位で適用しなければならない（MUST）。
- **FR-011**: クイック操作ポップアップは、現在のページが「現在の `ホスト名[:ポート番号]` と完全一致する通常パターン」以外のルール（パス指定パターン、正規表現パターン、またはポート付きページにおけるポートなし親ホストパターン）で一致している場合、ワンクリック変更・解除をロックし、一致中のパターン表示と設定画面への誘導を提供しなければならない（MUST）。
- **FR-012**: システムは、ページ全体の再読み込みを伴わない画面内でのURLパス変化を検知した際、Favicon・ページ内バッジ・ツールバーアイコンの適用および元状態への復元を即座に再評価しなければならない（MUST）。
- **FR-013**: システムは、開発者コンソールへの環境情報出力について、初期読み込み時および画面内遷移によって判定結果の環境が切り替わったときのみ出力し、同一環境にとどまるパス遷移時には重複出力してはならない（MUST NOT）。
- **FR-014**: オプション設定画面のURLチェッカーは、入力された検証用URLに対して実運用と同一の正規化・一致判定・優先順位ルールを適用し、最終的に採用された1つのパターン入力行のみを一致状態として強調表示しなければならない（MUST）。

### Key Entities

- **URLパターン設定 (URL Pattern Rule)**: 環境識別の条件を表す単一ルール。正規化済みのパターン文字列（ホスト名・任意のポート番号・任意のパス、または正規表現文字列）、正規表現フラグ、有効/無効フラグ、および優先順位比較に用いる詳細度を持つ。
- **評価対象ロケーション (Target Page Location)**: 開いているWebページまたはURLチェッカーに入力された検査対象アドレス。小文字化されたホスト名、実効ポート番号、大文字・小文字を維持したパス、およびポップアップ操作・一時OFFの基準となる `ホスト名[:ポート番号]` 識別子から成り、クエリとハッシュは含まない。
- **環境マッチング結果 (Environment Match Result)**: 優先順位評価を経て一意に決定された環境設定、採用されたURLパターン設定、およびクイック操作ポップアップでの直接編集可否（完全一致／ロック対象）を表す情報。
- **一時ミュート対象ホスト (Muted Host Entry)**: ブラウザ起動中のみバッジ表示を一時停止するサイトの識別子。`ホスト名[:ポート番号]` 単位で保持され、ブラウザ再起動時に自動解除される。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: ユーザーは、同一ホスト上の異なるポート（例: `localhost:3000` と `localhost:8080`）や異なるサブディレクトリ（例: `example.com` と `example.com/stg`）の環境識別設定を、設定画面またはポップアップから1分以内に登録・確認できる。
- **SC-002**: ホスト名のみ・ポート指定・パス指定・正規表現が混在する設定において、境界ケース（類似パス `/staging`、パスの大文字小文字違い、クエリ付きURL、親子ルールの優先順位競合）を含む全検証パターンで環境判定およびURLチェッカーの正答率が 100% となる。
- **SC-003**: 既存のホスト名設定および既存のホスト名向け正規表現パターン（例: `^.*\.local$`）を持つユーザー環境において、手動修正なしで 100% の既存ルールがアップデート前と同一の一致結果を維持する。
- **SC-004**: ページ再読み込みを伴わない画面内パス遷移が発生してから 1秒以内に、ツールバーアイコン・ページ内バッジ・Faviconの表示が遷移先の環境状態（または対象外時の復元状態）へ切り替わる。
- **SC-005**: パス指定・正規表現・親ホストルールで一致中のページにおいて、ポップアップ上の誤クリックによる既存パターンの意図しない削除・上書きの発生件数を 0件に保つ。

## Assumptions

- 拡張機能の動作対象スキームは従来通り通常の Web ページ（`http:` および `https:`）のみとし、ブラウザ内部設定ページや拡張機能ストア等の制限ページは対象外とする。
- クエリパラメータ（`?...`）およびハッシュフラグメント（`#...`）による環境判定は本機能のスコープ外とし、入力時・判定時ともに除外する。
- オプション設定画面における環境セクション（本番・ステージング・開発・カスタム）自体の並び順変更機能は本スコープには含めず、親子パターンの競合はすべて詳細度ルールによって解決する。
- 既存の自動保存の応答性、多言語対応（日本語・英語）、およびライト・ダークモードの視覚基準をそのまま維持する。
