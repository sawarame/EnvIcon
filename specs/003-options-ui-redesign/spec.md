# Feature Specification: オプション設定画面のUIレイアウト刷新と操作性向上 (Options UI Redesign)

**Feature Branch**: `003-options-ui-redesign`

**Created**: 2026-11-13

**Status**: Draft

**Input**: User description: "この拡張機能のオプション画面を使いやすくブラッシュアップしたいのですが、どのようにすればいいか案をもらえますか。（grill-meインタビューにより、左右2カラム階層化・リアルタイムプレビュー・トグル連動・URL入力ヒント・ヘッダー識別バッジの仕様に合意）"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 左右2カラム階層化と広域URLパターン一覧による快適な環境設定 (Priority: P1)

ユーザーは環境カード内で「どのように見えるか（バッジ外観・表示設定）」と「どこに適用するか（対象URLパターン一覧）」が左右2カラムで明確に分かれたレイアウトで設定を行う。左カラムはスリムな設定幅（310px）にコンパクトに集約され、右カラムがカードの残り全幅を広大に占有するため、ポートやパスを含む長いURLや正規表現パターンも窮屈さを感じずに快適に閲覧・入力できる。

**Why this priority**: オプション画面で最も頻繁に行われる「適用するURLを設定する」という操作において十分な横幅を確保し、現在の3カラムによる過密感と依存関係のわかりにくさを根本から解消するため。

**Independent Test**: 任意の環境で左カラムで文字や色を設定し、右カラムでURLパターンを追加・編集して保存が正常に行われ、広い横幅で表示されることで独立して検証可能。

**Acceptance Scenarios**:

1. **Given** ユーザーがオプション設定画面を開いている時, **When** 特定の環境カードを表示すると, **Then** 左側にスリムな「バッジ外観と表示設定（310px）」、右側に最大化された「対象URLパターン一覧（1fr）」が左右横並び配置される。
2. **Given** ポート番号やパスを含む長いURLを入力する時, **When** 右カラムの入力欄に入力すると, **Then** 入力欄の横幅が十分に広く確保され、文字列が途切れず快適に閲覧・編集できる。
3. **Given** 画面幅が狭い端末やウィンドウ（スマートフォンや左右分割時）の時, **When** オプション画面を表示すると, **Then** 左右レイアウトが崩れることなく、上部に「バッジ外観と表示設定」、下部に「対象URLパターン一覧」の順で自然な1カラム縦積みに切り替わる。

---

### User Story 2 - 機能トグルの状態に応じた付随設定のスマート連動 (Priority: P2)

ユーザーは各環境でFavicon書き換え、ページ内バッジ表示、コンソールログ出力の各機能を個別に有効/無効化できる。特にページ内バッジが無効（OFF）になっている場合、関連する「表示位置」や「文字サイズ」の設定項目が画面から非表示になり、不要な入力項目で画面が散らからない。再度有効（ON）に切り替えると、これらの設定項目がスムーズに再表示される。

**Why this priority**: 不要なオプションを非表示にすることで初心者や設定不要なユーザーの認知負荷を大幅に下げ、設定項目間の主従関係を明確にするため。

**Independent Test**: ページ内バッジのトグルをOFFにした際に位置やサイズ設定が非表示になり、ONに戻すと元の設定値を維持したまま再表示されることを確認することで独立して検証可能。

**Acceptance Scenarios**:

1. **Given** ページ内バッジが有効（ON）の状態の時, **When** ユーザーがページ内バッジのトグルを無効（OFF）に切り替えると, **Then** バッジの表示位置選択や文字サイズ入力欄が非表示となり、左カラム内の余計な余白が削減される。
2. **Given** ページ内バッジが無効（OFF）の状態の時, **When** ユーザーがトグルを再度有効（ON）に切り替えると, **Then** 以前設定されていた表示位置や文字サイズの設定値が保持された状態で再度表示される。
3. **Given** Favicon書き換えやコンソールログ出力のトグルが存在する時, **When** 各トグルを切り替えると, **Then** 他の表示項目に悪影響を与えることなく該当機能の有効/無効フラグが更新される。

---

### User Story 3 - URLパターンの書き方ヒントとヘッダー識別バッジによる一覧性向上 (Priority: P3)

ユーザーは各環境カードの右カラム上部に配置された簡潔な書き方ヒントを見ることで、ポート番号（例: `localhost:3000`）やパス指定（例: `example.com/stg`）が可能であることを即座に理解できる。また、各環境カードのヘッダーには環境名に加えて現在のバッジのミニプレビュー（色・文字）と登録ルール件数（例: `3件のルール` / `3 rules`）が表示され、画面をスクロールしながらでも目的の環境を瞬時に見分けられる。

**Why this priority**: 初心者がつまずきやすいURLパターンの指定ルールを明示し、環境数が増えた場合でもスクロール中に一目で目的の環境を識別できるようにするため。

**Independent Test**: 新規URLパターン追加時にヒント表示を確認でき、ヘッダーにバッジ色・文字およびパターン件数が正確に反映されることを確認することで独立して検証可能。

**Acceptance Scenarios**:

1. **Given** ユーザーがURLパターン一覧（右カラム）を確認する時, **When** 一覧の上部を見ると, **Then** ホスト名だけでなくポート番号やパスも指定可能である旨の簡潔なヒントメッセージが表示されている。
2. **Given** 各環境カードのヘッダーを表示する時, **When** 環境カードの上部を見ると, **Then** 環境名の横に現在のバッジ文字と配色を模した小さなピル型ミニバッジが表示され、登録されているURLパターンの総件数（例: `2 rules`）が表示される。
3. **Given** URLパターンを追加・削除した時, **When** 件数が変動すると, **Then** ヘッダーの登録パターン件数表示が即座に最新件数へ同期・更新される。

---

### Edge Cases

- **長い文字列の入力**: バッジ文字は最大4文字に制限されているが、全角文字や絵文字が入力された場合でもプレビュー領域のレイアウトが崩れず収まること。
- **不正なカラーコードの入力**: 不正なHEXカラーコードが入力された場合、プレビュー領域ではフォールバック色（直前の有効色またはデフォルト色）で安全に描画され、エラー表示（赤枠・バリデーションメッセージ）が適切に維持されること。
- **URLパターンが0件の場合**: 最後の1行は削除不可の制限を維持しつつ、件数表示が `1 rule` 等で正しく表示されること。
- **既存のURLチェッカーとの連動**: URLチェッカーでパターンが一致した際、右カラム内の該当行ハイライト（`.match-success`）が新レイアウトでも正常に動作すること。
- **言語切り替え（英語/日本語）**: 英語と日本語の両方において、新設されたヒント文章や件数表示（単数・複数形）、プレビュー関連のテキストが正しく切り替わること。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムは各環境カードを「バッジ外観と表示設定（左: 310px）」と「対象URLパターン一覧（右: 1fr）」の左右2カラム階層レイアウトで表示しなければならない（MUST）。
- **FR-002**: システムは画面幅が狭い表示領域（モバイルまたはウィンドウ狭幅時）において、2カラムを「上: バッジ設定 / 下: URLパターン一覧」の1カラム縦積みレイアウトへ自動的にレスポンシブ切り替えしなければならない（MUST）。
- **FR-003**: システムは右カラムのURLパターン一覧にグリッドの最大幅を割り当て、長いURLや正規表現を快適に閲覧・入力可能にしなければならない（MUST）。
- **FR-004**: システムは各環境ごとにFavicon書き換え、ページ内バッジ表示、コンソールログ出力の各機能トグルを提供しなければならない（MUST）。
- **FR-005**: システムはページ内バッジトグルが無効（OFF）の場合、バッジ表示位置および文字サイズの設定項目を非表示とし、有効（ON）の時のみ表示しなければならない（MUST）。
- **FR-006**: システムは右カラムのURLパターン一覧上部に、ポート番号やパス指定が利用可能であることを示す簡潔な書き方ヒント文を表示しなければならない（MUST）。
- **FR-007**: システムは各環境カードのヘッダーに、環境名に加えて現在のバッジ文字・色を反映したミニバッジおよび登録パターン件数バッジを表示しなければならない（MUST）。
- **FR-008**: システムはURLパターンの追加・削除・編集時に、ヘッダーのパターン件数表示をリアルタイムに更新しなければならない（MUST）。
- **FR-009**: すべての新規追加テキスト（ヒント文、件数ラベル等）は日本語および英語に対応し、言語切り替えに連動しなければならない（MUST）。
- **FR-010**: ライトモードおよびダークモードの双方において、プレビュー領域・左右カラム・ヒント表示が適切なコントラストとデザイン一貫性を維持しなければならない（MUST）。

### Key Entities *(include if feature involves data)*

- **環境設定 (EnvironmentConfig)**: 各環境の識別情報。本機能では既存のデータ構造（`id`, `name`, `badgeText`, `badgeColor`, `badgeOutlineColor`, `faviconEnabled`, `pageBadgeEnabled`, `consoleLogEnabled`, `pageBadgePosition`, `pageBadgeFontSize`, `hostnames`）をそのまま維持し、保存データの破壊的変更を伴わない。
- **ホスト名/URLパターン (HostnamePattern)**: 各環境に属するルール項目（`value`, `isRegex`, `enabled`）。右カラムにおいて一覧表示・追加・編集・並び替えを行う。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: デスクトップ表示時に右カラム（URLパターン一覧）がカード全体の大部分（約70%以上）を占有し、ポートやパスを含む長いURLの視認性と入力快適性が大幅に向上すること。
- **SC-002**: ページ内バッジが無効の環境において、不要な位置・サイズ設定が非表示化されることで、左カラムの縦方向の表示高さ・占有スペースが約30%削減されること。
- **SC-003**: 画面幅960px以下の狭幅端末でもレイアウト崩れなく1カラム縦積みに切り替わり、すべての設定項目にアクセスできること。
- **SC-004**: 環境カードのヘッダーを一瞥するだけで、カード本文を詳細に読まなくても目的の環境（バッジ色および登録パターン数）を即座に判別できること。

## Assumptions

- 既存のストレージ構造（`EnvironmentConfig`）に対するプロパティの追加・削除は行わず、UIレイアウトと表示・操作性の改善に特化する。
- 環境カード自体の折りたたみ（開閉）は行わず、すべての環境カードを常時展開する現行の運用方針を維持する。
- 既存の自動保存機構（500msデバウンス、バリデーションエラーポップオーバー）およびURLチェッカーとの完全な互換性を維持する。
- PrimeVue v4コンポーネントおよびAuraテーマのカラートークンに準拠してスタイリングを行う。
