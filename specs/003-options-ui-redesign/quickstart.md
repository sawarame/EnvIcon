# 動作確認・クイックスタートガイド (Quickstart & Validation Guide): オプション設定画面のUIレイアウト刷新

**Branch**: `003-options-ui-redesign` | **Date**: 2026-11-13 | **Spec**: [spec.md](./spec.md)

本ガイドは、オプション設定画面のUIレイアウト刷新（`specs/003-options-ui-redesign/spec.md`）が正常に完了したことを開発者がエンドツーエンドで検証するための手順書です。

---

## 1. ビルド検証 (Build Verification)

プロジェクトルートで以下のコマンドを実行し、TypeScript の厳格型検査および Webpack バンドルが正常に完了することを確認します。

```bash
npm run build
```

**期待される結果**:
- コンパイルエラー、型エラー（`any` 型不正等）、構文エラーが 0 件であること。
- `package/js/options.js` が正常に出力・更新されること。
- ルート直下に配布用 `package.zip` が生成されること。

---

## 2. Chrome デベロッパーモードでの動作確認手順

### 2.1 準備
1. Google Chrome を起動し、アドレスバーに `chrome://extensions` を入力して開きます。
2. 画面右上の「デベロッパーモード」を有効にします。
3. 「パッケージ化されていない拡張機能を読み込む」をクリックし、リポジトリの `package/` ディレクトリを選択します（既に読み込み済みの場合は再読み込みアイコンをクリック）。
4. ツールバーの EnvIcon アイコンを右クリックし、「オプション」を選択してオプション設定画面を開きます。

---

### 2.2 シナリオ別検証手順

#### シナリオ 1: 左右2カラムレイアウトとレスポンシブ切り替えの検証 (`User Story 1`, `FR-001`, `FR-002`)
1. **通常幅（PC）**:
   - 各環境カード（PROD / STG / DEV / カスタム環境）が表示されていることを確認します。
   - 左側に「バッジ外観と表示設定」、右側に「対象URLパターン一覧」が左右横並びで表示されていることを確認します。
2. **狭幅（レスポンシブ）**:
   - ブラウザのウィンドウ幅を狭める（約 960px 未満）か、DevTools のデバイスモードで表示します。
   - 左右レイアウトが崩れることなく、上部に「バッジ設定」、下部に「URLパターン一覧」の縦積みに自動的に切り替わることを確認します。

#### シナリオ 2: リアルタイムプレビューの検証 (`User Story 1`, `FR-003`, `SC-001`)
1. 任意の環境カード（例: DEV）の「バッジ文字」入力欄に文字（例: `test`）を入力します。
2. 左カラム上部の「バッジプレビュー」領域内の Favicon 風アイコンおよびページ内バッジ風テキストが、キー入力と同時に（遅延なく即座に）更新されることを確認します。
3. カラーピッカーで「バッジ文字色」や「フチドリ色」を変更した際、プレビューの文字色とフチドリ輪郭が即座に追従することを確認します。

#### シナリオ 3: ページ内バッジトグルによるスマート連動・スリム化の検証 (`User Story 2`, `FR-004`, `FR-005`, `SC-002`)
1. 「ページ内バッジ」のトグルスイッチをクリックして無効（OFF）にします。
2. 直下の「表示位置（Select）」および「文字サイズ（InputNumber）」の入力項目が非表示になり、左カラムの高さがスリム化されることを確認します。
3. 再度トグルをクリックして有効（ON）に戻すと、元の設定値（表示位置・文字サイズ）が保持された状態でスムーズに再表示されることを確認します。
4. Favicon 書き換えやコンソールログ出力のトグルも正常に ON/OFF 切り替えできることを確認します。

#### シナリオ 4: URL書き方ヒントと行入力・URLチェッカー連動の検証 (`User Story 3`, `FR-006`, `SC-003`)
1. 右カラム上部に、ポート番号やパスも指定可能である旨のヒントメッセージ（`urlPatternsHint`）が表示されていることを確認します。
2. URLパターンの入力欄が横にゆったりと広く確保され、長いURL（例: `localhost:3000/api/v1/health`）でも見切れることなく入力できることを確認します。
3. 画面上部のアコーディオン「URLチェッカー」を開き、一致するURLを入力した際、右カラム内の該当行に緑色の `.match-success` ハイライトが正常に付与されることを確認します。

#### シナリオ 5: カードヘッダーのミニバッジおよびルール件数の検証 (`User Story 3`, `FR-007`, `FR-008`, `SC-004`)
1. 各環境カードのヘッダータイトル横に、現在のバッジ文字とカラーを反映したピル型ミニバッジが表示されていることを確認します。
2. ミニバッジの横に登録パターン件数（例: `1 件のルール` や `3 rules`）が表示されていることを確認します。
3. 右カラムで「+ パターンを追加」ボタンをクリックしたり、既存行を削除した際、ヘッダーの件数表示がリアルタイムにインクリメント/デクリメントされることを確認します。

#### シナリオ 6: 多言語切り替えおよびテーマ切り替えの検証 (`FR-009`, `FR-010`)
1. ヘッダーの右上のメニュー（3本線アイコン）から言語を「日本語」⇄「English」と切り替えます。
   - 新規追加されたプレビューラベル、URLヒント文、ルール件数表記（単数/複数形含む）が正しく翻訳されることを確認します。
2. ヘッダーの月/太陽アイコンをクリックして「ダークモード」⇄「ライトモード」を切り替えます。
   - 2カラム境界線、プレビュー枠、ヒント文の文字色・背景色のコントラストが自然に追従し、視認性が維持されることを確認します。
