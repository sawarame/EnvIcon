# 技術調査および設計判断書 (Research & Design Decisions): オプション設定画面のUIレイアウト刷新と操作性向上

**Branch**: `003-options-ui-redesign` | **Date**: 2026-11-13 | **Spec**: [spec.md](./spec.md)

本ドキュメントは、オプション設定画面のUIレイアウト刷新（`specs/003-options-ui-redesign/spec.md`）における技術選定、レイアウト構造、コンポーネント分割、および設計判断の根拠を記録します。

---

## 1. カード内レイアウト構造の再設計（3カラムから左右2カラム階層化へ）

### 決定内容 (Decision)
既存の3カラムグリッド（`機能トグル` / `バッジ外観` / `ページ内バッジ詳細`）およびカード下部全幅の `ホスト名リスト` を廃止し、**「左カラム: バッジ外観と表示設定」** と **「右カラム: 対象URLパターン一覧」** の左右2カラム分割レイアウトへ移行する。
デスクトップ（`min-width: 961px`）では幅比率をおよそ `4.5 : 5.5`（または `1fr 1.2fr`）とし、画面幅 `960px` 以下の狭幅表示時は「上: バッジ設定 / 下: URLパターン一覧」の自然な1カラム縦積みへレスポンシブに切り替える。

### 採用理由 (Rationale)
1. **主従関係と関心事の分離**: ユーザーにとっての設定の関心事は「どのように表示させるか（見た目・挙動）」と「どのWebサイトに適用するか（対象URL）」の2つに大別される。左右に明確に分割することで、カード内の認知的負荷が大幅に低下する。
2. **URLパターンの横幅確保**: これまでカード下部に配置されていたホスト名・URLパターンは、ポート番号（`:3000`）やパス（`/stg`）を含む長いURLを入力する際に窮屈だった。右カラムを丸ごとURLパターン管理エリアとすることで、入力欄の横幅を大きく確保できる。
3. **高さのバランス最適化**: 左カラムにバッジ設定・プレビュー・トグルをまとめ、右カラムに複数行のURLパターンを並べることで、左右の高さが近くなり、カード内の無駄な空白領域を最小化できる。

### 検討した代替案 (Alternatives Considered)
- **タブ切り替え方式（「URLルール」「外観デザイン」「詳細オプション」）**: カード内の表示要素は減るものの、設定全体を一目で把握できず、タブのクリック操作が増加するため不採用。
- **基本設定と詳細設定の折りたたみ（アコーディオン）方式**: 開閉の手間が生じ、初見ユーザーが詳細設定の存在に気づきにくくなる可能性があるため、常時表示の左右2カラムを優先。

## 2. リアルタイムプレビュー領域の実装設計

### 決定内容 (Decision)
左カラムの最上部に「バッジプレビュー（Badge Preview）」領域を新設する。
プレビューには以下の2要素をコンパクトに並べて表示する:
1. **Favicon調プレビュー**: `32x32px` のブラウザタブ風アイコンボックス。四角形角丸、白背景（ダークモード時はダーク背景）、中央下部に設定中の `badgeText`（大文字最大4文字）を `badgeOutlineColor` のフチドリと `badgeColor` の文字色で描画（Canvas ではなく CSS の `text-shadow` を用いた高速・軽量なリアルタイム描画）。
2. **ページ内バッジ調プレビュー**: 右側に配置。半透明背景（`opacity: 0.5`）、`badgeColor` の文字、`text-shadow` によるフチドリを再現したインラインプレビュー。

### 採用理由 (Rationale)
1. **即時フィードバック**: 設定値を変更した際に、実際のWebページ上でどのように見えるかを保存前に直感的に確認できる。
2. **描画パフォーマンス**: CSS（`text-shadow`、`color`、`background`）によるリアクティブなスタイルバインディングを用いることで、Canvas の再生成コストをゼロにし、入力に対する遅延のないリアルタイム追従（`SC-001`）を実現する。
3. **不正入力への堅牢性**: 不正な HEX カラーが入力されている間は、直前の有効色またはデフォルト色でフォールバック表示し、プレビュー自体の表示崩れを防止する。

### 検討した代替案 (Alternatives Considered)
- **`OffscreenCanvas` や実際の Favicon 描画ロジックの直接呼び出し**: Canvas の生成や Data URL 変換処理は非同期になりやすく、テキスト入力時のデバウンスや CPU コストが高いため、CSS による即時レンダリングを採用。
- **カードヘッダーのみでのプレビュー**: カード上部に小さなミニバッジは置くが、Favicon風のフチドリやサイズ感をしっかり確認するには左カラム内のプレビュー領域が不可欠であると判断。

## 3. 機能トグルと付随設定のスマート連動（表示位置・文字サイズの表示制御）

### 決定内容 (Decision)
左カラム内の機能トグル群において、各機能の有効/無効トグルを配置する:
- **Favicon書き換えトグル**: `faviconEnabled`（デフォルト: ON）
- **コンソールログ出力トグル**: `consoleLogEnabled`（デフォルト: ON）
- **ページ内バッジ表示トグル**: `pageBadgeEnabled`（デフォルト: ON）
  - **付随オプション連動**: `pageBadgeEnabled` が `true` の場合のみ、直下に「表示位置（Select）」と「文字サイズ（InputNumber）」の設定ブロックを表示（`v-if` または スライドトランジション）。`false`（OFF）に切り替えた場合は、これらの設定項目を非表示とし、左カラムの縦幅をスリム化する（`SC-002`）。

### 採用理由 (Rationale)
1. **不要な情報の非表示化**: ページ内バッジを使わない環境（Favicon のみ変更したい場合など）において、無関係な位置やサイズの入力欄を非表示にすることで、初心者にとっても設定項目がシンプルでわかりやすくなる。
2. **状態保持**: 非表示になっても `pageBadgePosition` や `pageBadgeFontSize` の既存設定値はメモリ上に保持されるため、再度トグルを ON にした際も以前の値が復元される。

### 検討した代替案 (Alternatives Considered)
- **非活性（disabled）＋半透明での常時表示（現行仕様）**: 入力欄の枠が残り続け、画面の縦幅を占有してしまうため、非表示化によるスリム化を採用。
- **トグル横のギア（⚙）アイコンポップオーバー**: 余白は削れるが、階層が深くなり操作ステップが増えるため、インラインでの動的開閉を採用。

## 4. URLパターン一覧（右カラム）の書き方ヒントと行レイアウトの最適化

### 決定内容 (Decision)
`src/options/components/HostnameList.vue` を改修し、右カラム内で独立したセクションとして成立するレイアウトへ再構成する:
1. **見出しとヒントブロック**:
   - 上部に「対象URLパターン」の見出し、およびポート番号やパスが指定可能である旨の簡潔なヒントメッセージ（`pi pi-info-circle` 付き）を表示。
2. **行レイアウトの最適化**:
   - 右カラムの広い横幅を活かし、各行の「ドラッグハンドル」「有効トグル」「Regexチェック」「URLパターン入力欄」「削除ボタン」を水平に配置。
   - `InputText` に十分な flex 伸縮性を持たせ、長いURLでも見切れないようにする。
   - 下部に「+ URLパターンを追加」ボタンを配置。

### 採用理由 (Rationale)
1. **ユーザーのつまずき防止**: EnvIcon の強力なポート・パス指定（例: `localhost:3000`, `example.com/stg`）を知らずにホスト名のみを入力してしまうユーザーに対し、入力欄のすぐ上で自然に書き方をガイドできる。
2. **視認性向上**: 入力欄の表示可能文字数が従来の約1.5倍に拡大し、複雑な正規表現や長いURLもスクロールせずに確認できるようになる。

## 5. カードヘッダーの強化（ミニバッジおよびルール件数の常時表示）

### 決定内容 (Decision)
各環境カード（`EnvSection.vue`）のヘッダータイトル横に、以下の2つの視覚バッジを追加する:
1. **ヘッダーミニバッジ (`.env-header-mini-badge`)**: 現在の `badgeText`（大文字最大4文字）を、設定された `badgeColor`（背景色）と `badgeOutlineColor`（文字色・枠線）で描画したピル型ミニバッジ。
2. **ルール件数バッジ (`.env-header-rules-badge`)**: 登録されているURLパターン配列の総件数（例: `3件のルール` / `3 rules`）をミュートトーンの小バッジで表示。
3. **カード展開方針**: カードの折りたたみ機能は追加せず、全カードを常時展開する現行方針を維持する（ユーザー合意に基づく）。

### 採用理由 (Rationale)
1. **高速な環境識別**: 複数の環境が登録されている場合でも、カード上部の環境名とミニバッジ・件数を一瞥するだけで、目的の環境カードを瞬時に識別できる（`SC-004`）。
2. **操作の手間削減**: 折りたたみ操作を挟まないため、ワンアクションで即座に入力可能。

## 7. 憲章・技術制約との整合性チェック

- **コンテキスト分離**: すべての変更は Options UI（`src/options/`）内で完結し、Background や Content Script には影響を与えない。
- **データ永続化**: `EnvironmentConfig` のスキーマ変更はなく、既存の Chrome Storage データと 100% 互換性を保つ。
- **型安全性**: `strict: true` を遵守し、新規 Props / Emits に厳格な TypeScript インターフェースを適用する。
- **アクセシビリティ**: プレビューやトグル連動において、適切な `aria-label` およびコントラスト比を確保する。
