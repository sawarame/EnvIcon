# クイックスタート・検証ガイド (Quickstart & Validation): 保存エラー表示時のマウスオーバーによる不備理由表示

**対象機能**: [spec.md](./spec.md) (`002-save-error-hover-reasons`)
**関連契約**: [validation-and-popover-ui.md](./contracts/validation-and-popover-ui.md)
**データモデル**: [data-model.md](./data-model.md)

## 1. 前提条件とビルド検証

### 必要環境
- Node.js（LTS）および npm
- Google Chrome ブラウザ（Manifest V3 対応版）

### ビルドおよび型検証コマンド
リポジトリルートで以下のコマンドを実行し、TypeScript の厳格型チェック（`strict: true`）・Webpack 本番バンドル・`package.zip` 生成がエラーなく完了することを確認する。

```bash
npm run build
```

**期待される結果**:
- 終了コード `0` で完了すること。
- `package/js/options.js` を含むバンドル群が更新され、型エラーやビルド警告が発生しないこと。

### Chrome への拡張機能読み込み
1. Chrome で `chrome://extensions/` を開き、「デベロッパーモード」を有効にする。
2. `package/` ディレクトリを読み込む（読み込み済みの場合は更新アイコンをクリックする）。
3. EnvIcon のオプション設定画面（拡張機能の「オプション」またはポップアップ右上の歯車ボタン）を開く。

## 2. エンドツーエンド検証シナリオ

### シナリオ 1: 単一不備発生時のマウスオーバー表示と正常時の非表示（User Story 1）
1. 初期状態（フッター右下に緑色で「すべての変更を自動保存しました」が表示されている状態）で、保存ステータスにマウスカーソルを重ねる。
   - **確認**: 吹き出しが表示されないこと（`FR-002`）。
2. 「本番環境（Production）」の URL パターン欄に `http://example.com:99999`（範囲外ポート）を入力し、500ms 待つ。
   - **確認**: フッター右下ステータスが「入力内容に不備があるため保存されていません」に変わり、カーソルを合わせると詳細確認可能であることを示すポインター変化が見られること。
3. 保存エラー表示（アイコンまたはテキスト）にマウスカーソルを重ねる。
   - **確認**: フッター上方に吹き出しが見切れずに表示され、「本番環境（Production）」の見出しと `http://example.com:99999` の形式無効を示す理由が表示されること。
4. 吹き出し上にカーソルを移動し、その後吹き出しと保存エラー表示の両方からカーソルを外す。
   - **確認**: 吹き出し上にカーソルがある間は表示が維持され、両方から離れた時点で速やかに閉じること。

---

### シナリオ 2: 全7種の不備判別・重複元環境の明示・未入力環境名の代替表示（User Story 2）
1. 「+ 環境追加」でカスタム環境を1つ追加し、以下の入力を行って複合エラーを発生させる：
   - カスタム環境の「環境名」を空欄にする
   - カスタム環境のバッジ「色」に `#zzzzzz`、「フチ色」に `invalid` を入力する
   - カスタム環境の URL パターン1行目（Regex ON）に `[unclosed` を入力する
   - 本番環境に `example.com`、ステージング環境に `https://Example.COM/`（異環境重複）と、ステージング環境の2行目に `example.com`（同一環境または本番との重複）を入力する
2. 保存エラー表示にマウスカーソルを重ねる。
   - **確認**:
     - 環境順・項目順にすべての不備理由が一覧表示されること。
     - 環境名が空欄のカスタム環境が「（名称未設定の環境）」として表示され、環境名未入力・色不正・フチ色不正・正規表現構文エラーがすべて列挙されること。
     - 重複しているパターン行について、「本番環境（Production）」と重複している旨（同一環境内重複の場合は同じ環境内で重複している旨）が明記され、画面上の赤枠強調行と完全に一致すること。

---

### シナリオ 3: 多数のエラー発生時の内部スクロールと修正・取り消し追従（User Story 2 & Edge Cases）
1. パターン行を追加して不正な文字列を 10行以上入力し、10件以上の不備を同時に発生させる。
2. 保存エラー表示にマウスカーソルを重ね、そのまま吹き出し内部へカーソルを移動してホイールスクロールする。
   - **確認**: 吹き出しが画面外へはみ出さず、吹き出し内の縦スクロールで先頭から末尾まですべての不備理由を確認できること（`SC-004`）。
3. 不備を1つずつ修正し、最後に残った環境の「編集内容を取り消す（Undo）」ボタン（または環境削除ボタン）をクリックして直前の保存済み状態へ戻す。
   - **確認**: 修正のたびにリストから解消項目が消え、すべての不備が解消された瞬間に保存エラー表示が消えて「すべての変更を自動保存しました」へ確実に復帰すること（エラー表示が残留しないこと：`SC-003`）。

---

### シナリオ 4: 多言語切り替え・ライト/ダークモード・キーボードフォーカス検証（User Story 3）
1. いずれかの環境に不備を発生させた状態で、画面右上メニューから言語を `日本語` → `English` へ切り替え、保存エラー表示にマウスオーバーする。
   - **確認**: ステータステキスト・環境名（未設定ラベルや重複元環境名を含む）・不備理由のすべてが英語表示に切り替わっていること。
2. ヘッダーのテーマ切り替えボタンでライトモードとダークモードを切り替え、それぞれでマウスオーバーする。
   - **確認**: 両テーマで背景色・枠線・文字色のコントラストが適切に保たれ、明瞭に判読できること。
3. キーボードの `Tab` キーでフッターの保存エラー表示へフォーカスを当て、続けて `Escape` キーを押す。
   - **確認**: フォーカス時にマウスオーバーと同様の吹き出しが表示され、`Escape` キーまたはフォーカス離脱で閉じること。
